## 1. Executive Summary

Gnosis is a Koine Greek learning app that teaches through AI-powered conversation. The text-to-speech feature — the cornerstone of the voice mode experience — is currently broken: the browser's Web Speech API spells out Greek characters instead of pronouncing them, likely due to polytonic diacritics confusing the Modern Greek TTS engine. This spec defines a three-phase approach: fix the immediate bug, integrate Google Cloud TTS as a reliable interim solution, and build a custom open-source Koine Greek voice model trained on public domain data following the Buth "Living Koine" pronunciation system.

## 2. Problem Statement

### 2.1 The Problem

The TTS system in Gnosis does not pronounce Koine Greek text — it spells out individual characters. This renders voice mode (the primary learning interaction) effectively unusable. Users cannot hear how Greek words and sentences should sound, which fundamentally undermines the app's communicative language learning approach.

### 2.2 Current State

- **TTS Engine**: Browser-native Web Speech Synthesis API (`window.speechSynthesis`)
- **Voice Selection**: Modern Greek (`el-GR`) voices, falling back to system default
- **Configuration**: Speech rate 0.85, pitch 0.95, language hint `el-GR`
- **Key Files**: `src/hooks/useTextToSpeech.ts`, `src/components/chat/SpeakButton.tsx`
- **Root Cause**: Polytonic Greek diacritics (breathing marks, circumflex accents, iota subscripts) in the Koine Greek text generated by the LLM are not recognized by Modern Greek TTS engines. The engine falls back to character-by-character spelling when it encounters these unfamiliar diacritical marks.
- **No backend audio processing**: All TTS happens client-side, making it browser-dependent and inconsistent across platforms.

### 2.3 Impact Analysis

- Voice mode is the primary learning interaction — without working TTS, the core product value is broken
- Users cannot develop listening comprehension or pronunciation skills
- The app cannot compete with traditional audio-based Greek learning resources (Kantor, Buth recordings)
- No competitor has solved programmatic Koine Greek TTS, so fixing this creates a genuine differentiator

### 2.4 Business Value

- **Cornerstone feature**: TTS is required for the communicative "Living Koine" teaching method the app is built around
- **Commercial differentiator**: No existing product offers programmatic Koine Greek TTS — this would be a first
- **Open-source opportunity**: A custom Koine TTS model could be open-sourced, building community credibility while powering the commercial product
- **User retention**: Working voice mode is the difference between a functional learning tool and a broken prototype

## 5. Functional Requirements

### 5.1 Feature: Polytonic-to-Monotonic Text Preprocessing

**Priority**: P0 (Critical)

#### User Stories

**US-001**: As a learner, I want to hear Greek words pronounced correctly so that I can learn proper pronunciation.

**Acceptance Criteria**:
- [ ] Greek text with polytonic diacritics (breathing marks, circumflex, iota subscript) is converted to monotonic form before passing to any TTS engine
- [ ] The preprocessing uses Unicode NFD decomposition to strip combining diacriticals (U+0300 grave, U+0342 circumflex, U+0313/U+0314 breathings, U+0345 iota subscript), then recomposes with NFC
- [ ] Diaeresis marks are preserved (they affect pronunciation)
- [ ] The browser Web Speech API pronounces Greek words correctly after preprocessing
- [ ] Preprocessing runs on all text before TTS — both manual "Listen" button and voice mode auto-play

**Edge Cases**:
- Text containing mixed Greek and English (e.g., transliterations in parentheses): Preprocessing should only apply to Greek Unicode ranges
- Empty or whitespace-only text: Skip TTS gracefully
- Text with no polytonic diacritics: Pass through unchanged

## 7. Technical Considerations

### 7.1 Architecture Overview

```
[LLM Text Stream (Groq)] --> [Polytonic Preprocessing] --> [TTS Router]
                                                              |
                                            +-----------------+-----------------+
                                            |                 |                 |
                                      [Cache Lookup]  [Google Cloud TTS]  [Custom Model]
                                            |                 |                 |
                                            v                 v                 v
                                      [Audio Stream] --> [Client Audio Player]
```

The TTS system sits between the LLM text output and the client audio player. Text is preprocessed (polytonic to monotonic), then routed through a priority chain: cache → custom model → Google Cloud TTS → browser fallback.

### 7.2 Tech Stack
- **Frontend**: React hooks for audio playback (`useTextToSpeech.ts` refactored), Web Audio API for streaming
- **Backend**: Next.js API route (`/api/tts`) for server-side TTS orchestration
- **Cloud TTS**: Google Cloud Text-to-Speech API (WaveNet/Chirp 3 HD, `el-GR`)
- **Custom Model**: Piper TTS or Coqui/VITS, hosted on Modal or Replicate (serverless GPU)
- **Storage**: S3-compatible storage for audio cache + CDN
- **Pronunciation**: JSON dictionary with IPA mappings for SSML phoneme tags

### 7.3 Integration Points

| System | Integration Type | Purpose |
|--------|-----------------|---------|
| Google Cloud TTS | REST API | High-quality Greek TTS with SSML phoneme support |
| Modal / Replicate | Serverless API | Custom model inference hosting |
| Groq API (existing) | Streaming API | Text source — TTS processes streamed text chunks |
| S3-compatible storage | Object storage | Audio cache for pre-generated pronunciations |
| CDN | Edge network | Fast delivery of cached audio files |

### 7.4 Technical Constraints
- **No copyrighted training data**: Custom model must use only public domain or permissively licensed audio
- **Meta MMS CC-BY-NC**: Cannot deploy Meta's `mms-tts-ell` model directly in commercial product; can use architecture/approach for reference
- **Budget**: Total TTS infrastructure cost under $10/month at moderate usage
- **Browser compatibility**: Server-side TTS ensures consistent behavior across all browsers (replacing browser-dependent Web Speech API for primary use)
- **Koine Greek is not a supported language code**: No TTS engine supports `grc` (Ancient Greek); all implementations use Modern Greek (`el-GR`) as the base

## 13. Appendix

### 13.1 Glossary

| Term | Definition |
|------|------------|
| Koine Greek | The common dialect of Greek spoken from ~300 BCE to ~300 CE; the language of the New Testament |
| Buth "Living Koine" | A reconstructed pronunciation system for Koine Greek developed by Randall Buth, based on scholarly evidence of 1st-century pronunciation |
| Polytonic Greek | Greek text with full historical diacritical marks (breathing marks, circumflex, iota subscript) — used in Ancient/Koine Greek texts |
| Monotonic Greek | Modern Greek orthography using only acute accent and diaeresis — what Modern Greek TTS engines expect |
| SSML | Speech Synthesis Markup Language — XML-based markup for controlling TTS pronunciation, prosody, and other aspects |
| IPA | International Phonetic Alphabet — standardized system for representing speech sounds |
| Piper TTS | Open-source neural TTS system supporting custom voice training via VITS architecture |
| VITS | Variational Inference with adversarial learning for end-to-end Text-to-Speech — a neural TTS architecture |
| NFD/NFC | Unicode Normalization Forms — Decomposed (NFD) and Composed (NFC) forms used for diacritical manipulation |
